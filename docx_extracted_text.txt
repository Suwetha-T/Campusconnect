1.1.CYBERSECURITY FUNDAMENTALS
Cybersecurity is the practice of protecting computer systems, networks, applications, and data from unauthorized access, attacks, damage, and theft. During the internship, I learned the fundamental concepts of cybersecurity and understood the importance of protecting digital systems against continuously evolving cyber threats.
The CIA Triad is one of the fundamental concepts of cybersecurity. Confidentiality – ensures that information is accessible only to authorized individuals or systems. Encryption and access control mechanisms are commonly used to maintain confidentiality.
Integrity – ensures that data remains accurate, consistent, and protected from unauthorized modification. Hashing and checksums are commonly used to verify data integrity.
Availability – ensures that authorized users can access systems and resources whenever required. Redundancy, backups, and fault-tolerant systems help maintain availability.
During the internship, I also learned about common types of malware, including viruses, worms, trojans, ransomware, spyware, adware, and rootkits. Understanding these malware categories helped establish the foundation for developing an automated malware detection system.
1.2.ARTIFICIAL INTELLIGENCE AND MACHINE  LEARNING
Artificial Intelligence enables computer systems to perform tasks that normally require human intelligence, such as recognizing patterns, analyzing data, and making decisions.Machine Learning is a subset of Artificial Intelligence in which systems learn patterns from data and use the learned patterns to make predictions on new data.In the malware detection project, supervised machine learning was used. The model was trained using labelled examples of benign and malicious files. After training, the model learned the structural and statistical patterns associated with different classes of executable files.The major benefits of applying machine learning to malware detection include:
Ability to identify previously unseen malware variants based on learned patterns.
Reduced dependence on manually created signatures.
Ability to analyze multiple file characteristics simultaneously.
Faster classification after model training.
Possibility of detecting patterns associated with zero-day malware.
I also learned that machine learning-based cybersecurity systems have limitations, including the requirement for high-quality labelled datasets, the risk of overfitting, adversarial evasion, computational requirements, and model interpretability challenges.
     1.3. STATIC MALWARE ANALYSIS AND PE FILES
Static malware analysis is the process of examining a file without executing it. This approach is safer than executing unknown malware and can provide useful information about the internal structure of executable files.Windows executable files commonly use the Portable Executable (PE) format. PE files include executable files such as .exe files and other related formats.During the internship, I learned how the PEFile Python library can be used to parse PE files and extract useful structural information.The extracted information includes:
PE header information
Number of sections
Code and data sizes
Address of entry point
Image base
Section entropy
Import information
Export information
Resource information
Characteristics and header flags
These features can be represented as numerical values and provided as input to a machine learning model for malware classification.

2.4.TASK ON WEEK FOUR
 SHILD-AI Based Malware Detection Using Flask Framework
INTRODUCTION
In week four , I started to build our own project in our cybersecurity domain. The AI Based Malware Detection System is a full-stack web application combining static malware analysis with supervised machine learning to classify Windows executables as Benign or Malware. It has three major components: a feature-extraction pipeline that parses the PE structure of an uploaded file, a trained Random Forest classifier that performs the prediction, and a Flask web application that handles the interface, upload workflow and result persistence. Unlike signature-based tools, it relies entirely on structural and statistical characteristics of the PE header (imports, section entropy, size, header flags), executing the full pipeline — upload to prediction and history logging — in seconds. The interface uses a dark, cybersecurity-themed, fully responsive design, with all scans logged to an SQLite history database.
Objectives
Design a machine learning system to classify PE files as Benign or Malware.
Implement static feature extraction using PEFile (headers, sections, import/export tables).
Train, evaluate and compare Random Forest, Decision Tree and SVM classifiers.
Maximize accuracy while minimizing false positives.
Build a Flask web app for upload and real-time prediction, with an SQLite scan history.
Create a responsive, cybersecurity-themed UI, and evaluate models on accuracy, precision, recall, F1 and ROC-AUC.
Document the full development lifecycle and identify directions for future enhancement.
Existing System
Traditional antivirus software matches a file's hash or byte pattern against a database of known malware signatures — fast, cheap and low false-positive for known threats, but with key limitations:
Cannot detect zero-day malware until a vendor analyzes and catalogues a sample.
Evaded by polymorphic/metamorphic malware that alters its own signature.
Requires frequent database updates and constant connectivity.
Signature databases become unwieldy to search as they grow into the hundreds of millions.
Purely reactive — detection only follows prior identification of a threat.
Proposed SystemThe proposed system replaces exact signature matching with a classifier trained on structural/statistical PE features (section entropy, import anomalies, header metadata), learning generalizable patterns rather than exact matches. It detects unseen variants without connectivity, returns a confidence score for transparency, keeps a searchable scan history, and is built entirely from open-
source tools.

System Architecture
The pipeline flows linearly: the user accesses the web app → uploads an .exe file → features are extracted via PEFile (headers, sections, imports, entropy) → preprocessed (scaling/encoding) → passed to the trained Random Forest model → a Benign/Malware prediction with confidence score is returned → displayed to the user → and stored in the SQLite history table.
         
Figure 2.1: System Architecture / Workflow Diagram
Module Descriptions
User Interface – HTML5/CSS3/Jinja2 pages for home, upload, results and history.
File Upload – validates and safely stores uploaded files (Flask request.files, secure_filename).
Feature Extraction – parses PE structure with PEFile (headers, sections, imports/exports).
Preprocessing – converts raw features into the numerical vector expected by the model.
Prediction – loads model.pkl via Joblib and returns class + confidence.
Database – SQLite3 persists filename, prediction, confidence and timestamp for the history page.
Methodology
Data Collection – EMBER dataset plus supplementary Kaggle PE samples, pre-labelled benign/malicious.
Data Cleaning – removed rows with excessive missing values; imputed minor gaps with medians.
Feature Engineering – selected discriminative header/section attributes; dropped correlated or low-variance ones.
Model Training – 80:20 stratified split; Random Forest, Decision Tree and SVM trained via Scikit-learn with grid-search tuning.
Model Testing – evaluated with accuracy, precision, recall, F1 and ROC-AUC; confusion matrix per model
Model Saving – best model (Random Forest) serialized with Joblib alongside its feature-column order.Flask Integration – model loaded once at startup; routes handle upload, prediction and history.
Deployment – run locally via Flask's dev server, portable to Gunicorn/Docker for production.
TOOLS AND TECHNOLOGIES USED
 Python
Python, created by Guido van Rossum (1991), is a high-level, readable, dynamically typed language with an extensive package ecosystem, making it the natural choice here thanks to its mature ML stack (Scikit-learn, Pandas, NumPy), native PE parsing (PEFile) and lightweight web framework (Flask).
Flask Framework
Flask is a lightweight WSGI micro-framework that provides only the essentials, leaving other choices (ORM, auth) to the developer — well suited to a project of this size. It follows an MVC-like pattern: routes act as controllers, Jinja2 templates as views. Routes are bound to URL paths via decorators for the home page, upload/prediction endpoint and history page (GET/POST as appropriate), with Jinja2 rendering dynamic content using {{ }} / {% %} syntax.
SQLite
SQLite is a lightweight, serverless, file-based database included in Python's standard library, chosen for its zero-configuration setup. It stores a single scan_history table (filename, prediction, confidence, timestamp).
PEFile
PEFile parses the Portable Executable format used by Windows .exe/.dll/.sys files, exposing the DOS header, NT headers, section table, and import/export/resource directories — the raw source of every feature used for classification.
Pandas, NumPy, Matplotlib and Seaborn 
Pandas' DataFrame structure organizes extracted features and prepares training data; NumPy provides the underlying numerical operations. Matplotlib and Seaborn were used during model development to generate confusion matrices, ROC curves and correlation heatmaps.
